## Resultado implementado

- Drizzle ORM 0.45.2, Drizzle Kit 0.31.10 y mysql2 3.22.6 fijados.
- Better Auth 1.6.25 estable; sus cuatro tablas fueron generadas con el CLI
  oficial y revisadas para ULID `CHAR(26)` y `DATETIME(3)`.
- Dieciséis tablas en total, FKs e índices de ownership.
- `message_parts` omitida expresamente.
- Dos migraciones reproducibles: inicial y upgrade del índice de entidad sync.
- Pool pequeño con fechas UTC y BIGINT sin pérdida.
- Escritura de conversación y `sync_changes` en la misma transacción.
- Migración remota bloqueada salvo confirmación exacta de host/base.
- Backup local no sobrescribible y restauración con registro centinela.
- Workflow de CI aislado para la matriz de datos.

## Evidencia local

Pasaron:

```bash
source scripts/env.sh
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:check
pnpm db:migrate:test
pnpm test:db
pnpm db:compat:test
pnpm db:restore:test
pnpm db:explain
```

Matriz:

```text
MySQL    8.4.8                    utf8mb4_0900_ai_ci  6/6 tests
MariaDB  11.8.8-MariaDB-ubu2404  utf8mb4_unicode_ci  6/6 tests
```

Las suites prueban base vacía, segunda aplicación idempotente, upgrade
0000→0001, 16 tablas, ausencia de `message_parts`, ULID, `DATETIME(3)`, FKs,
ownership, entidad+changelog y rollback total.

`EXPLAIN` eligió índices para conversaciones, mensajes, memorias y pull de
sincronización. Backup/restauración recuperó el registro centinela.
