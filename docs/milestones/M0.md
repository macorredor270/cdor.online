## Evidencia

Pasaron:

```bash
source scripts/env.sh
./scripts/check-toolchain.sh
pnpm install --frozen-lockfile
pnpm check
pnpm build:platform
pnpm build:mobile
cargo fmt --manifest-path apps/mobile/src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path apps/mobile/src-tauri/Cargo.toml \
  --all-targets --all-features -- -D warnings
cargo check --manifest-path apps/mobile/src-tauri/Cargo.toml
pnpm --dir apps/mobile tauri build --no-bundle
```

El servidor generado por `@sveltejs/adapter-node` arrancó y respondió HTTP 200.

Una copia limpia instaló:

```bash
pnpm install --frozen-lockfile --filter @cdor/platform...
```

Después compiló `apps/platform` sin crear `apps/mobile/node_modules` ni instalar
`@tauri-apps/cli`. Esto demuestra que el flujo previsto para Hostinger no
compila ni instala el subgrafo móvil.

## Riesgos pendientes

- El NDK instalado no se congela como requisito del proyecto hasta superar una
  compilación Android real.
- Tauri advierte que `online.cdor.app` termina en `.app`, sufijo que puede
  confundirse con la extensión de bundles macOS. Se conserva porque es un
  identificador cerrado por el documento rector y se revisará antes de iOS.
- Android Studio no es necesario para los checks de M0; sí deberá estar
  disponible antes del flujo visual y de depuración Android si las herramientas
  de línea de comandos resultan insuficientes.

No se han iniciado contratos, base de datos, backend ni frontend funcional.
