# M7 — Streaming SSE

Estado: completado.

## Resultado local

- `POST /api/v1/chat/stream` valida Principal y contrato antes de abrir SSE.
- `POST /api/v1/chat/cancel` registra cancelación en MySQL y aborta el proceso
  local cuando corresponde.
- La creación del mensaje de usuario, mensaje assistant, generación,
  idempotencia y `sync_changes` ocurre en una transacción.
- Repetir la operación devuelve `IDEMPOTENCY_CONFLICT` con el ID y estado de
  la generación existente; no se almacena ni reproduce el stream.
- NVIDIA se traduce a `start`, `delta`, `usage`, `done` y `error` propios.
- Los deltas se agrupan cada 30 ms o 512 bytes.
- Se guarda snapshot cada segundo o 4 KiB, no por token.
- Un sondeo MySQL cada segundo permite que una cancelación alcance otro
  proceso aunque NVIDIA esté temporalmente sin emitir.
- La desconexión del consumidor aborta upstream y persiste estado cancelado.
- Las generaciones con más de cinco minutos se reconcilian de forma
  oportunista y mediante `pnpm maintenance:generations`; no hay worker.
- Se permiten como máximo dos generaciones activas por usuario, serializando
  la comprobación mediante lock de su fila.
- La canary sintética está protegida por un token server-only y no usa NVIDIA
  ni MySQL.

- Se creó el backup previo
  `backups/production-pre-m7-20260728T221358Z.sql` con permisos `0600` y

  `5c43ef33d09302d8ef207abdf9b919014f782ebafe80c33825c8de579274ad58`.
- Las tres migraciones se aplicaron manualmente: 16 tablas de aplicación y
  `__cdor_migrations` con tres registros. La aplicación y CI no ejecutan
  migraciones automáticas.
- `/health` y `/health/ready` devolvieron estado correcto después de migrar.
- La canary sintética de cinco minutos produjo 1.198 ticks en 300.838 ms,

  `502` ni `504`.
- `pnpm smoke:stream:real:hostinger` creó una cuenta Better Auth interna sin
  abrir el registro público, obtuvo un bearer firmado, abrió el stream NVIDIA,
  canceló tras `start` y comprobó en MySQL:
  `generation_requests.state=cancelled`,
  `messages.status=cancelled` e `idempotency_keys.state=failed`.
- La misma canary pasó en Node `24.18.0` usando `fetch` para la cancelación.
  Node `26.4.0`, fuera del toolchain fijado, mostró un bloqueo de su conexión
  HTTP/2 experimental; el modo HTTP/1.1 independiente confirmó que el servidor
  sí acepta y persiste la cancelación.
- La cuenta y sus filas canary se eliminan en `finally`. La IP local se
  autorizó únicamente durante la migración/verificación y después se revocó;
  permanece solo la IPv6 interna de Hostinger.

## Riesgos pendientes

- El límite de dos streams por usuario es provisional hasta las pruebas de
  carga de M14.
- Una caída entre snapshots puede perder hasta un segundo o 4 KiB del texto
  parcial, que quedará marcado como fallido durante reconciliación.
- El rate limiting temporal persistente se endurecerá en M14; M7 limita
  concurrencia y conserva ownership e idempotencia.

## Condición exacta de detención

M7 se cerró después de:

1. configurar `STREAM_CANARY_TOKEN` en Hostinger y local;
2. desplegar exclusivamente el artefacto platform;
3. superar `pnpm smoke:stream:hostinger` durante cinco minutos;
4. ejecutar un stream NVIDIA real desplegado y confirmar que cancelar cierra
   upstream y deja estados MySQL coherentes.

Si Hostinger bufferiza o corta, se documenta la evidencia y se detiene el
milestone para decidir VPS o polling.
