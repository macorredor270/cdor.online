# M2 — Validación

Estado: completado el 27 de julio de 2026.

## Resultado

Las fronteras conocidas antes de implementar rutas funcionales quedan
validadas en runtime:

- límites compartidos en `@cdor/contracts`;
- tamaño de texto medido en bytes UTF-8 cuando el plan especifica KiB;
- queries numéricas sin coerciones silenciosas;
- errores normalizados con `path` y `code`, sin copiar valores privados;
- validación explícita de salidas;
- payload JSON limitado a 1 MiB durante la lectura real del stream;
- rechazo de media types no JSON y de cuerpos comprimidos;
- configuración privada validada bajo `apps/platform/src/lib/server`;
- escaneo con canarios de los bundles web y móvil.

La configuración no se evalúa durante el build: se carga de forma diferida en
el servidor. Esto permite compilar sin credenciales y falla al solicitar una
configuración incompleta. Los errores enumeran variables, nunca sus valores.

## Evidencia

Pasaron:

```bash
source scripts/env.sh
pnpm install --frozen-lockfile
pnpm test:validation
pnpm check
pnpm test
pnpm build:platform
pnpm build:mobile
pnpm scan:client-secrets
cargo check --locked --manifest-path apps/mobile/src-tauri/Cargo.toml
```

Resultados:

```text
Contratos            5 archivos, 23 tests
Platform             2 archivos, 10 tests
Suite M2 específica  18 tests
Bundles escaneados   web y mobile, sin nombres ni valores privados
```

La suite específica incluye seis tests de límites/errores compartidos, diez de
entorno/payload y dos que demuestran que el detector acepta un bundle limpio y
falla ante una referencia a `NVIDIA_API_KEY`.

## Riesgos pendientes

- Un proxy podría descomprimir un cuerpo antes de entregarlo a Node y retirar
  `Content-Encoding`; el contador de bytes posterior sigue aplicando 1 MiB,
  pero el comportamiento real de Hostinger se verificará con sus rutas.
- La barrera `src/lib/server` la aplica SvelteKit. El escaneo independiente
  protege los artefactos, pero cualquier paquete compartido futuro deberá
  mantener fuera la configuración privada.
- La contraseña MySQL mostrada en capturas continúa considerándose
  comprometida y debe rotarse antes de M3.
- Todavía no se conocen la versión y collation reales del MySQL de Hostinger;
  esa es una condición obligatoria de M3, no una suposición de M2.

## Condición de detención

La puerta de M2 está superada: todas las fronteras existentes tienen esquema,
los errores son estables, el límite de payload se aplica en bytes y los bundles
cliente no contienen nombres ni valores sensibles. El trabajo se detiene aquí;
no se crean esquemas MySQL, migraciones ni repositorios.
