# M14 — Seguridad, rendimiento y producción

Estado: release candidate desplegado y canary SSE verificada; lanzamiento
bloqueado por la carga concurrente de Hostinger, la restauración remota y las
aprobaciones externas pendientes.

## Resultado

- Cada respuesta recibe `x-request-id`, CSP, `nosniff`, `DENY`, Referrer Policy,
  Permissions Policy, COOP/CORP y HSTS únicamente en producción HTTPS.
- El access log estructurado registra solo request ID, método, pathname, estado
  y duración; nunca query strings, cookies, bearer, payloads ni contenido de
  chat.
- `production:preflight` exige Node/HTTPS/secretos privados y mantiene el
  registro cerrado; no ejecuta migraciones.
- `production:smoke` verifica health, cabeceras y 401 de la API sin sesión.
- `production:load` ejecuta carga HTTP acotada (1–50 workers, hasta 10.000
  requests) y devuelve P50/P95/P99 sin datos privados.
- El workflow manual `Production gate` genera un artefacto filtrado de
  `apps/platform`; el workflow de Hostinger sigue siendo el único publicador.
- No se ejecutan compilaciones iOS/IPA en GitHub Actions. El proyecto iOS y el
  plugin Keychain permanecen versionados para una compilación manual en macOS
  cuando existan las credenciales Apple.

## Evidencia pública del 2026-07-29

- `https://cdor.online/health` y `/health/ready` responden `200`.
- `/api/v1/conversations` sin sesión responde `401` (`UNAUTHENTICATED`).
- La respuesta pública contiene HSTS, `nosniff`, `DENY`, Referrer Policy,
  Permissions Policy, COOP y CORP.
- La canary SSE real completó 300.813 s, 1.198 ticks, primer tick a 571 ms,
  separación máxima de 824 ms y evento `done`.
- La carga acotada 10×50 completó (P50 3.173 ms, P95 6.583 ms, P99
  7.581 ms). Las pruebas 25×50 y 50×50 agotaron el timeout de cliente de
  10 s; por tanto Hostinger no supera todavía la puerta de carga del plan.

## Riesgos pendientes

- Hostinger/MySQL/NVIDIA reales requieren smoke protegido y carga 10/25/50 con
  credenciales autorizadas. La canary no llama a NVIDIA ni escribe MySQL.
- El backup remoto de Hostinger se creó sin tocar producción, pero la
  restauración de verificación no pudo autenticarse con el usuario temporal.
  No se declara backup/restore de producción hasta que hPanel asigne permisos
  al usuario temporal o permita restablecerlo.
- Los workflows de GitHub no son necesarios para el despliegue actual y no se
  ejecutan; el artefacto filtrado se publica mediante la rama `hostinger`.
- `apps/platform/src/routes/privacy` y `terms` se reescribieron con estructura
  RGPD completa en [M15](./M15.md); sigue pendiente la revisión por un
  profesional jurídico. El registro público continúa cerrado.
- iOS queda bloqueado hasta disponer de Apple Developer, certificado,
  provisioning y aprobación de App Store; la compilación será manual en macOS,
  fuera de GitHub Actions.

## Condición exacta de detención

La v1 no se declara lanzada ni se abre el registro. M14 solo se cierra después
de que backup/restore remoto, carga 10/25/50, escaneo de
dependencias/secretos, revisión legal y build iOS manual en macOS pasen con
evidencia. La canary SSE ya pasó. Como 25×50 y 50×50 superan el timeout,
Hostinger queda fuera de la capacidad objetivo y el lanzamiento se detiene
hasta optimizar el servicio o migrar la API a un VPS según el runbook.
