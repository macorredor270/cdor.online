# M10 — Integración Tauri

Estado: completado.

## Resultado

- El núcleo M9 está alojado en estado Rust y todo acceso SQLite se despacha
  fuera del hilo principal.
- Svelte dispone de un bridge TypeScript tipado para caché, outbox, sync,
  autenticación, chat y cancelación, sin SQL ni peticiones sensibles.
- Better Auth se consume desde Rust. El bearer no vuelve al WebView.
- Android persiste la sesión cifrada con AES/GCM y una clave no exportable de
  Android Keystore; iOS usa Keychain.
- El stream SSE se procesa en Rust y se entrega mediante eventos agrupados
  `chat://*`.
- La capability del WebView no concede acceso a los commands del plugin de
  secretos y no existe plugin shell.
- La consola técnica temporal abre y reabre caché, autentica, guarda en outbox,
  sincroniza, envía streaming y cancela.
- Se generó y compiló el proyecto Android Tauri para ARM64. La plataforma API
  36 se instaló en un SDK local porque `/opt/android-sdk` no es escribible.

## Riesgos pendientes

- El plugin Keychain está implementado pero solo podrá compilarse y probarse en
  macOS; no existe un workflow de IPA en GitHub Actions. La firma y publicación
  iOS siguen bloqueadas hasta disponer de credenciales Apple.
- La conectividad de M10 es una comprobación por resultado de red; M11 debe
  medir cambio Wi-Fi/datos, interrupción y reanudación en el Xiaomi.
- WAL sigue desactivado hasta las pruebas de cierre forzado en el dispositivo.
- El APK debug incluye símbolos y no representa tamaño ni rendimiento release.

## Condición exacta de detención

M10 se cierra al disponer de una consola técnica capaz de autenticar, encolar,
reabrir caché, sincronizar, iniciar/cancelar chat, con sesión inaccesible al
